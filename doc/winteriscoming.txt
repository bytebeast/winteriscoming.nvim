1. INTRODUCTION                                         *winteriscoming-intro*

A port of John Papa's Winter is Coming theme for VS Code, with Treesitter,
LSP semantic tokens, and highlights for many plugins. Integrations load
automatically for the plugins lazy.nvim or |vim.pack| has installed.

==============================================================================
2. STYLES                                              *winteriscoming-styles*

  winteriscoming-blue      Dark Blue: the signature navy (`#011627`)
  winteriscoming-black     Dark Black: charcoal (`#282822`)
  winteriscoming-light     Light: white, with the original light mapping
  winteriscoming           your `style`, or `light_style` when
                           'background' is "light"

Changing 'background' after loading switches between your dark and light
style.

==============================================================================
3. SETUP                                                *winteriscoming-setup*

With LazyVim: >lua
  return {
    { "winteriscoming.nvim", lazy = false, priority = 1000, opts = {} },
    { "LazyVim/LazyVim", opts = { colorscheme = "winteriscoming" } },
  }
<
Without LazyVim: >lua
  require("winteriscoming").setup({ style = "blue" })
  vim.cmd.colorscheme("winteriscoming")
<

4. OPTIONS                                            *winteriscoming-options*

All options with their defaults: >lua
  require("winteriscoming").setup({
    style = "blue",          -- "blue", "black" or "light"
    light_style = "light",   -- used when 'background' is "light"
    transparent = false,     -- don't set the editor background
    terminal_colors = true,  -- set g:terminal_color_*
    hide_inactive_statusline = false,
    italics = true,          -- false drops every italic
    bold = true,             -- false drops every bold
    styles = {
      comments = { italic = true }, keywords = { italic = true },
      functions = {}, variables = {},
      properties = {}, attributes = {}, parameters = {},
      types = {}, strings = {}, operators = {},
      virtual_text = {}, inlay_hints = {},
      mutable = {}, readonly = {}, statics = {}, globals = {},
      sidebars = "dark",     -- "dark", "transparent" or "normal"
      floats = "dark",       -- "dark", "transparent" or "normal"
    },
    bright_line_numbers = false,
    faithful = false,
    dim_inactive = false,
    contrast = "normal",     -- or "high"
    subtle_comments = false,
    colorblind = false,      -- or "red-green", "blue-yellow"
    saturation = 1,
    accent = "blue",
    rainbow = "vivid",       -- or "dimmed", "mono"
    rainbow_variables = false,
    diagnostics = { underline = "undercurl", virtual_text = "tinted" },
    inlay_hints = "tinted",  -- or "plain"
    borderless = false,
    bright_borders = false,
    lualine_bold = false,
    on_colors = function(colors) end,
    on_highlights = function(highlights, colors) end,
    cache = true,
    plugins = { all = nil, auto = true },
  })
<
Invalid values are reported once and replaced by their defaults.

                                              *winteriscoming-opt-italics*
italics ~
  Master switch. When false, no group is italic, whatever `styles` says.

                                               *winteriscoming-opt-styles*
styles ~
  Attributes per syntax category; any attr-list accepted by
  |nvim_set_hl()|. Comments and keywords are italic by default. The VS Code
  theme italicizes much more; to get that back: >lua
    styles = {
      functions = { italic = true },
      variables = { italic = true }, properties = { italic = true },
      attributes = { italic = true },
    }
<
                                   *winteriscoming-opt-bright_line_numbers*
bright_line_numbers ~
  VS Code paints every line number winter blue. By default only the
  current line is bright; set to true for the VS Code look.

                                             *winteriscoming-opt-faithful*
faithful ~
  This port adjusts a few colors for a terminal: functions (`periwinkle`
  instead of `frost`), variables (`mist` instead of `glacier`), constants
  (`violet` instead of `azure`, which matched functions almost exactly),
  the comment grey (a cool `#8a9db3` instead of `#999999`), docstrings
  (a quieter sage instead of the string mint) and the Dark
  Black selection. Set to true to use the exact VS Code values.

                                             *winteriscoming-opt-contrast*
contrast ~
  "high" lifts every syntax color below WCAG AA (4.5:1) up to it, and
  brightens comments, line numbers, inlay hints and muted UI text.

                                      *winteriscoming-opt-subtle_comments*
subtle_comments ~
  Fade comments toward the background: true (= 0.5), a fade from 0 to 1,
  or `{ fade = 0.7, docstrings = false }`. Measured in contrast, never
  below 1.6:1. A comment color set in `on_colors` is left alone.

                                           *winteriscoming-opt-colorblind*
colorblind ~
  "red-green" or "blue-yellow": git signs, diffs and diagnostics use
  colors that stay apart for that color vision deficiency. Syntax colors
  are untouched.

                                           *winteriscoming-opt-saturation*
saturation ~
  0 (greys) to 1 (full color). Each color keeps its contrast; git, diff
  and diagnostic colors keep at least 70% of their color.

                                               *winteriscoming-opt-accent*
accent ~
  Titles, badges, the selected tab, float borders and the normal-mode
  statusline. One of the names in `require("winteriscoming.config").accents`.

                                              *winteriscoming-opt-rainbow*
rainbow ~
  Rainbow delimiters and indent scopes: "vivid", "dimmed" (quieter than
  code) or "mono" (shades of grey by nesting depth).

                                    *winteriscoming-opt-rainbow_variables*
rainbow_variables ~
  A color per local variable and parameter, picked from its name, as in
  JetBrains IDEs. Needs an LSP that sends semantic tokens.

                                           *winteriscoming-opt-borderless*
borderless ~
  Telescope, snacks and fzf-lua pickers without border lines: prompt, list
  and preview are told apart by shade, titles become badges.

                                              *winteriscoming-opt-plugins*
plugins ~
  `auto` enables an integration only when lazy.nvim or |vim.pack| has the
  plugin. `all = true` enables everything; the default (nil) does that only
  when neither plugin manager is in use. Force one with its module or repo
  name: >lua
    plugins = { telescope = true, ["neo-tree"] = false }
<
                                                     *winteriscoming-diff*
Diffs ~
  Changed text inside a changed line (`DiffText`) is underlined in winter
  blue as well as tinted, so a one-character edit stands out. Added text
  inside a changed line (`DiffTextAdd`) is underlined in green. That needs
  Neovim 0.12+ with "inline:char" in 'diffopt' (the 0.12 default): >lua
    vim.opt.diffopt:append("inline:char")
<
  Folded lines use a neutral shade darker than the editor, so a fold never
  looks like a changed line. With 'cursorline' on, Neovim underlines the
  whole cursor line in diff windows; to keep only the changed text
  underlined, highlight just the line number there: >lua
    vim.api.nvim_create_autocmd({ "VimEnter", "WinEnter", "BufWinEnter", "OptionSet" }, {
      callback = function()
        for _, win in ipairs(vim.api.nvim_list_wins()) do
          vim.wo[win].cursorlineopt = vim.wo[win].diff and "number" or vim.go.cursorlineopt
        end
      end,
    })
<
  Inside tmux, colored underlines need `set -as terminal-features ",*:usstyle"`
  in ~/.tmux.conf (tmux 3.2+). To drop the underlines: >lua
    on_highlights = function(hl, c)
      hl.DiffText = { bg = c.diff.text }
      hl.DiffTextAdd = { bg = c.diff.text_add }
    end,
<

5. OVERRIDING COLORS                                *winteriscoming-overrides*

Highlight groups use roles (`colors.syntax.keyword`) that name palette
colors (`"ice"`). Names are resolved after `on_colors`, so changing a
palette color updates every role that uses it: >lua
  on_colors = function(c)
    c.ice = "#38c6ff"           -- keywords, operators, jump labels
    c.syntax.string = "#c3f5c6" -- just one role
    c.syntax.func = "frost"     -- point a role at another palette name
  end,
  on_highlights = function(hl, c)
    hl.LineNr = { fg = c.fg_muted }
  end,
<
Get the colors for statusline components and the like: >lua
  local colors = require("winteriscoming").colors()
<
`:checkhealth winteriscoming` lists the active integrations and options, and
warns when `on_colors` pushes a syntax color below WCAG AA.

7. LUALINE AND BUFFERLINE                             *winteriscoming-lualine*

Lualine: `theme = "auto"` picks up `winteriscoming`, or name a style
explicitly: `theme = "winteriscoming-light"`.

Bufferline: the tabs are themed without configuration, but bufferline builds
its file icon groups from its own `highlights` option, so the icons keep a
background derived from `Normal` unless you pass the colors. As a function,
bufferline re-reads them on every |:colorscheme|: >lua
  {
    "akinsho/bufferline.nvim",
    opts = function(_, opts)
      opts.highlights = function()
        return require("winteriscoming.groups.bufferline").highlights()
      end
    end,
  }
<
The function follows the loaded winteriscoming style and returns nothing
under another colorscheme.
